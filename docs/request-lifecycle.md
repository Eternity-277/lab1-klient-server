# lab1-klient-server
# Жизненный цикл запроса

## Сценарий UC: аналитик просматривает подозрительные транзакции

**Цель:** Security Analyst открывает страницу подозрительных случаев, чтобы просмотреть операции, которые система определила как потенциально мошеннические.

### 1. Действие пользователя

Аналитик входит в систему и нажимает пункт меню «Подозрительные случаи». Браузер отправляет GET-запрос на сервер, чтобы получить страницу со списком подозрительных случаев.

### 2. DNS

Браузер определяет IP-адрес сервера по доменному имени приложения с помощью DNS, если соответствующий адрес ещё не сохранён в кэше. При локальном запуске приложения обращение может выполняться через `localhost` без поиска внешнего домена.

### 3. Соединение (TCP/TLS)

При использовании HTTPS браузер устанавливает TCP-соединение и выполняет TLS-рукопожатие для защиты передаваемых данных. При локальной разработке приложение также может работать по HTTP, если HTTPS специально не настроен.

### 4. HTTP-запрос

Браузер отправляет запрос на страницу подозрительных случаев:

- **Метод:** `GET`
- **Путь:** `/SuspiciousCases/Index`
- **Заголовок:** `Cookie` — содержит идентификатор аутентификационной cookie, если пользователь уже вошёл в систему.
- **Заголовок:** `Accept: text/html` — указывает, что браузер может принять HTML-страницу.
- **Тело запроса:** отсутствует, поскольку используется GET-запрос.

Идентификатор пользователя не передаётся в URL или теле запроса. Сервер определяет пользователя по данным аутентификации.

### 5. Приём запроса

Запрос принимает веб-сервер приложения ASP.NET Core, после чего он передаётся в конвейер обработки HTTP-запросов. Маршрутизация ASP.NET Core MVC определяет контроллер `SuspiciousCasesController` и действие `Index`.

### 6. Обработка в Backend

Сначала ASP.NET Core проверяет аутентификацию пользователя и его права доступа. Если пользователь не вошёл в систему, приложение может перенаправить его на страницу входа; если у него нет роли Security Analyst или другого разрешённого доступа, сервер возвращает отказ в доступе.

Если проверка пройдена, `SuspiciousCasesController` вызывает метод соответствующего Service. Service получает список подозрительных случаев через Data Access (ADO.NET), при необходимости связывает их с данными транзакций и подготавливает результат для отображения.

### 7. Обращение к базе данных

Слой Data Access использует ADO.NET и MySQL-провайдер для выполнения SQL-запроса к базе данных. Например, запрос может читать записи из таблицы `SuspiciousCases` и связанные сведения из `Transactions`, чтобы получить идентификаторы случаев, статус проверки, дату и информацию о транзакциях.

Пример SQL-запроса:

```sql
SELECT
    sc.Id,
    sc.TransactionId,
    sc.Status,
    t.Amount,
    t.TransactionDate
FROM SuspiciousCases AS sc
INNER JOIN Transactions AS t
    ON sc.TransactionId = t.Id;
```

Названия таблиц и столбцов необходимо привести в соответствие с фактической структурой базы данных проекта. В этом сценарии выполняется чтение данных, поэтому операция `INSERT`, `UPDATE` или `DELETE` не требуется.

### 8. Ответ сервера

После получения данных Service передаёт результат контроллеру, а контроллер формирует HTML-страницу с помощью Razor View.

При успешном выполнении сервер возвращает:

- **Статус-код:** `200 OK`.
- **Формат:** `text/html; charset=utf-8`.
- **Заголовок:** `Content-Type: text/html; charset=utf-8`.
- **Содержимое:** HTML-страница со списком подозрительных случаев, их статусами и информацией о соответствующих транзакциях.

Если пользователь не аутентифицирован, сервер может вернуть перенаправление `302 Found` на страницу входа. При отсутствии необходимых прав возможен ответ `403 Forbidden`.

### 9. Обновление интерфейса

Браузер получает HTML-страницу и отображает её аналитику. Пользователь видит таблицу подозрительных случаев и может выбрать нужную запись для дальнейшего анализа или расследования.

## Итоговый путь запроса

**Security Analyst → Browser (Frontend) → HTTP/HTTPS → ASP.NET Core MVC → Authorization/RBAC → SuspiciousCasesController → Service → Data Access (ADO.NET) → MySQL → Backend → HTML-ответ → Browser**
