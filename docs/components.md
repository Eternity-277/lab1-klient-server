# lab1-klient-server
# Описание компонентов системы Fraud Detection System

## 1. Пользователи (Clients)

| Компонент | Назначение | Технология | Взаимодействует с |
|---|---|---|---|
| Bank Client | Позволяет клиенту просматривать свои банковские карты и транзакции. Без этого компонента клиент не сможет пользоваться системой через пользовательский интерфейс. | Веб-браузер, HTML | Frontend (HTTPS) |
| Security Analyst | Позволяет аналитику просматривать подозрительные транзакции, анализировать случаи мошенничества и вести расследования. Без этой роли нельзя будет выполнять анализ подозрительных операций. | Веб-браузер, HTML | Frontend (HTTPS) |
| Administrator | Позволяет администратору управлять пользователями и правилами обнаружения мошенничества. Без этой роли будет затруднено администрирование системы. | Веб-браузер, HTML | Frontend (HTTPS) |

## 2. Frontend — уровень представления

| Компонент | Назначение | Технология | Взаимодействует с |
|---|---|---|---|
| Frontend | Отображает страницы, таблицы и формы, с помощью которых пользователи работают с системой. Без него пользователям пришлось бы взаимодействовать с сервером напрямую. | HTML, CSS, Razor Views | Clients, Backend (HTTP/HTTPS, HTML и данные форм) |

## 3. Backend — уровень приложения

| Компонент | Назначение | Технология | Взаимодействует с |
|---|---|---|---|
| ASP.NET Core MVC | Принимает HTTP-запросы, направляет их соответствующим контроллерам и формирует ответы для браузера. Без него приложение не сможет обрабатывать пользовательские запросы и возвращать страницы. | C#, ASP.NET Core MVC | Frontend, модули приложения, MySQL через Data Access |
| Auth | Выполняет вход пользователя и обеспечивает проверку его аутентификации. Без него нельзя надёжно определить, кто работает с системой. | C#, ASP.NET Core Authentication | Frontend, Users, Authorization/RBAC |
| Users | Обеспечивает получение и управление данными пользователей. Без него будет невозможно централизованно хранить и обрабатывать информацию об учётных записях. | C#, ADO.NET | Auth, Authorization/RBAC, MySQL |
| BankCards | Обеспечивает получение и обработку сведений о банковских картах. Без него система не сможет связывать карты с пользователями и соответствующими транзакциями. | C#, ADO.NET | Users, Transactions, MySQL |
| Transactions | Обрабатывает банковские транзакции и предоставляет данные для проверки на признаки мошенничества. Без него система не сможет анализировать финансовые операции. | C#, ADO.NET | BankCards, FraudRules, SuspiciousCases, MySQL |
| FraudRules | Хранит и применяет правила выявления подозрительных операций. Без него автоматическая проверка транзакций по заданным условиям будет невозможна. | C#, ADO.NET | Transactions, Administrator, MySQL |
| SuspiciousCases | Регистрирует и хранит случаи, выявленные как потенциально мошеннические. Без него нельзя будет систематизировать подозрительные операции и отслеживать их обработку. | C#, ADO.NET | Transactions, FraudRules, Investigations, MySQL |
| Investigations | Обеспечивает ведение расследований подозрительных случаев и хранение их результатов. Без него аналитики не смогут последовательно фиксировать ход и итоги проверки. | C#, ADO.NET | SuspiciousCases, Security Analyst, MySQL |
| Authorization/RBAC | Проверяет права доступа на основе ролей пользователей. Например, клиент не должен получать административные возможности, а аналитик — управлять настройками администратора без соответствующих разрешений. Без него пользователи могли бы получать доступ к функциям, которые им не предназначены. | ASP.NET Core Authorization, C# | Auth, Users, все защищённые модули |

### Слои каждого модуля

**Controller → Service → Data Access (ADO.NET)**

- **Controller** принимает запросы и возвращает ответы.
- **Service** содержит бизнес-логику и правила обработки данных.
- **Data Access (ADO.NET)** выполняет SQL-запросы к базе данных и передаёт результаты приложению.

## 4. База данных — уровень хранения данных

| Компонент | Назначение | Технология | Взаимодействует с |
|---|---|---|---|
| MySQL | Хранит данные пользователей, банковских карт, транзакций, правил обнаружения мошенничества, подозрительных случаев и расследований. Без базы данных система не сможет надёжно сохранять информацию между запусками. | MySQL | Backend, Data Access (ADO.NET), SQL-запросы и результаты |

## 5. Внешние сервисы

| Компонент | Назначение | Технология | Взаимодействует с |
|---|---|---|---|
| Внешние сервисы отсутствуют | В первоначальной версии система использует собственную базу данных и внутренние модули. Поэтому подключение внешних платёжных или аналитических сервисов не требуется. | Не применяется | Внешние интеграции не предусмотрены |
